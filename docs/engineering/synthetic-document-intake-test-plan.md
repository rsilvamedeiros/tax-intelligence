## Fixtures e Red válido

Organizações A/B, ator somente A, ator nos dois escopos, analyst, reviewer, viewer e administrador; vínculo revogado e identidade não provisionada. Somente referências/valores sintéticos. PostgreSQL real isolado via TEST_DATABASE_URL, roles distintas de migrador/runtime e prova dos privilégios antes de testar RLS. Tokens RSA efêmeros; nunca banco de desenvolvimento/produto ou fallback DATABASE_URL.

Escrever o primeiro teste de cada comportamento, observar falha correspondente e implementar mínimo. Falha de conexão, role sem GRANT necessário, migration ausente ou erro de compilação não contam como Red de isolamento. Assertar SQLSTATE, linhas e efeitos, sem depender de texto de erro. Registrar separadamente regressões acrescentadas após implementação; não alegar TDD retroativo.

Verificar recusa antes do lock para quem não possui permissão e revalidação obrigatória depois da espera para quem passou na primeira consulta. GET também participa do protocolo de autorização; teste leitura bloqueada durante revogação e negação após seu commit. Deduplicação não substitui autorização, e eventos devem referenciar tenant/ator/recurso/request ID internos sem copiar o documento. Migration/constraints e rollback da aplicação precisam de ensaio com dados sintéticos existentes.

## Validação após implementação

Domínio puro, HTTP real, integração PostgreSQL das tabelas novas e API compilada com runtime restrito; regressões existentes de login/administração, lint, tipos, cobertura, build e scans. O BFF do ADR 0020 e sua jornada Keycloak/Chrome com efeito real foram aprovados no CI, conforme [evidências](synthetic-document-bff-validation.md). Interface do lote e testes RTL foram implementados no ADR 0021; evidência de navegador UI de INTAKE-11 aprovada no CI, e OTLP específico das novas rotas permanece pendente. Checks dependentes de ambiente só contam quando executados; docs apenas por links, formato e coerência.

INTAKE-01 está coberto por testes puros, partes de persistência têm evidência no ADR 0018 e POST/GET foram exercitados na API compilada do ADR 0019. O [ADR 0022](../adr/0022-synthetic-diagnostic-core.md) implementa somente o núcleo puro DEMO-TOTAL-001 e contrato de evidência; execução registrada/autorizada de diagnóstico, DB-03 das tabelas de controle e importação real continuam pendentes, mesmo se esta matriz futura passar.
